01

The whole thing, in one circle전체 구조는 하나의 원

Training is a loop of three phases that never stops. Each turn of the loop makes a slightly better player, which then generates slightly better data for the next turn. That feedback is the entire idea.

학습은 세 단계가 끝없이 도는 순환입니다. 한 바퀴 돌 때마다 조금 더 잘 두는 모델이 나오고, 그 모델이 다음 바퀴에 쓸 더 좋은 데이터를 만듭니다. 이 되먹임이 전부입니다.

02

The brain: one small network, two answers두뇌: 작은 신경망 하나, 답은 두 개

Show it a position and it answers two questions at once. Where would I play? — a probability for all 225 points. Am I winning? — one number from −1 to +1. Everything else in the project exists to make these two answers better.

판을 보여주면 두 질문에 동시에 답합니다. 어디에 둘까? — 225개 지점 각각의 확률. 내가 이기고 있나? — −1에서 +1 사이의 숫자 하나. 프로젝트의 나머지는 전부 이 두 답을 좋게 만들기 위해 존재합니다.

What the network actually sees신경망이 실제로 보는 것

Every plane is drawn from the point of view of whoever is about to move. The network is never told "you are white" — it always sees itself as plane 0. That single choice halves what it has to learn, and lets one game teach both colours.모든 평면은 지금 둘 차례인 쪽의 시점으로 만들어집니다. 신경망은 "너는 백이다"라는 말을 듣지 않습니다. 언제나 자기 자신이 평면 0입니다. 이 선택 하나로 배울 양이 절반이 되고, 한 판의 기록이 흑백 양쪽 공부가 됩니다.

Is it a ResNet? Yes — here is the whole modelResNet인가? 맞습니다 — 모델 전체는 이게 전부입니다

It is a residual tower in the AlphaZero style, not torchvision's ResNet: there is no pooling and no downsampling, so the board stays 15×15 from the first layer to the last. Every point keeps its own 96-number description all the way through.torchvision의 ResNet이 아니라 AlphaZero 방식의 잔차 타워입니다. 풀링도 다운샘플링도 없어서 첫 층부터 마지막 층까지 판은 계속 15×15입니다. 각 지점이 96개짜리 자기 설명을 끝까지 유지합니다.

# simplified — the real file is ~90 lines

class ResBlock(nn.Module):       # ← the "Res" in ResNet
    def forward(self, x):
        y = relu(bn1(conv1(x)))  # 3×3, 96ch, padding=1 → still 15×15
        y =      bn2(conv2(y))   # 3×3, 96ch
        return relu(x + y)       # ★ skip connection: learn the *change*

class OmokNet(nn.Module):
    def __init__(self):
        self.stem   = ConvBN(5, 96, k=3)                 # 5 planes → 96 channels
        self.blocks = [ResBlock(96) for _ in range(6)]   # the tower
        self.policy = PolicyHead(96, 4, 15)              # 1×1 conv→4ch → fc → 225
        self.value  = ValueHead (96, 2, 15, hidden=128)  # 1×1 conv→2ch → fc128 → 1 → tanh

    def forward(self, x):       # x: (B, 5, 15, 15)
        y = relu(self.stem(x))
        for b in self.blocks:
            y = b(y)            # shape never changes: (B, 96, 15, 15)
        return self.policy(y), self.value(y)
        #      (B, 225) logits     (B,) in [-1, +1]

Why the skip connection matters: x + y means each block only has to learn a small correction to what the previous block already understood. Without it, six stacked convolutions train badly. That one plus sign is the whole trick behind ResNet.스킵 커넥션이 중요한 이유: x + y 덕분에 각 블록은 앞 블록이 이미 파악한 것에 작은 보정만 배우면 됩니다. 이게 없으면 컨볼루션 여섯 층을 쌓았을 때 학습이 잘 되지 않습니다. 이 더하기 하나가 ResNet의 핵심입니다.

03

Thinking: 160 little experiments per move사고: 한 수마다 160번의 작은 실험

The network's first guess is a hunch. To turn a hunch into a move, the engine runs a search — and it always does the same four things, 160 times over. Step through it below.

신경망의 첫 감은 어디까지나 감입니다. 그 감을 한 수로 바꾸려고 엔진은 탐색을 돌립니다. 하는 일은 늘 같은 네 가지, 그것을 160번 반복합니다. 아래에서 한 단계씩 눌러 보세요.

PUCT search, one simulation at a timePUCT 탐색, 한 번에 한 시뮬레이션씩

sim 0 / 6
SELECT · 선택 Walk down from the root, always taking the child with the best Q + U score. 뿌리에서 아래로, 매번 Q + U 점수가 가장 높은 자식을 따라갑니다.
EXPAND · 확장 Hit a position never seen before? Add it to the tree as a new leaf. 처음 보는 국면에 닿으면 새 잎으로 트리에 추가합니다.
EVALUATE · 평가 Ask the network: priors P for every move, and one value v for this position. 신경망에 묻습니다. 각 수의 사전확률 P, 그리고 이 국면의 값 v.
BACKUP · 역전파 Send v back up the path, flipping its sign at every ply — your win is my loss. v를 왔던 길로 되돌려 보냅니다. 한 수마다 부호를 뒤집으면서 — 네 승리는 내 패배니까요.

After the last simulation the engine plays the most visited child — not the highest-scoring one. Visits are the honest vote: a move only accumulates them by surviving repeated scrutiny.마지막 시뮬레이션이 끝나면 엔진은 점수가 가장 높은 수가 아니라 가장 많이 방문된 수를 둡니다. 방문 수가 정직한 표입니다. 반복해서 검증받고 살아남아야만 쌓이니까요.

The one formula that decides where to look어디를 볼지 정하는 단 하나의 식

score(a) = Q(a) + c_puct · P(a) · √N(parent) / (1 + N(a))
Q(a) — how well this move has actually worked so far. Exploit.
Q(a) — 지금까지 이 수가 실제로 얼마나 잘 됐는지. 활용.
P(a) — the network's prior hunch, before any search. Unvisited moves ride on it alone. Explore.
P(a) — 탐색 전 신경망의 감. 아직 안 가본 수는 이것만 믿고 갑니다. 탐험.
N(a) — visit count. The more a move is tried, the smaller its exploration bonus gets, so attention drifts elsewhere.
N(a) — 방문 횟수. 많이 가본 수일수록 탐험 보너스가 줄어 관심이 다른 곳으로 옮겨갑니다.
c_puct = 1.6 · fpu_reduction = 0.25 · dirichlet(α=0.15, weight=0.25) at the root only

During self-play only, noise is mixed into the root priors so the engine is forced to try moves it does not believe in. Without it the loop would practise the same opening forever.자기대국 때만 뿌리의 사전확률에 잡음을 섞습니다. 스스로 믿지 않는 수도 억지로 시도하게 만들기 위해서입니다. 이게 없으면 같은 포석만 영원히 연습하게 됩니다.

04

Search sharpens the hunch — and the hunch is retrained on the result탐색이 감을 다듬고, 그 결과로 다시 감을 가르친다

This is the exact moment learning happens. The network's raw guess is soft and spread out. After 160 simulations the visit counts are sharper and better. That sharper distribution becomes the training target — so next time, the network guesses it directly.

학습이 일어나는 바로 그 지점입니다. 신경망의 날것 추측은 흐릿하게 퍼져 있습니다. 160번 시뮬레이션을 돌리면 방문 분포는 더 날카롭고 더 정확해집니다. 그 날카로운 분포가 학습 목표가 되고, 다음번엔 신경망이 그것을 바로 맞힙니다.

05

Learning: two targets, one loss학습: 목표는 둘, 손실은 하나

A self-play game is stored as a move list plus one policy vector per ply — about 20× smaller than storing the input tensors, and it means the encoding can change without throwing away the data. Training draws 512 random positions from the last 400,000 and takes one AdamW step.

자기대국은 수순 목록과 수마다의 정책 벡터로 저장됩니다. 입력 텐서를 저장하는 것보다 약 20배 작고, 인코딩을 바꿔도 기존 데이터를 버리지 않아도 됩니다. 학습은 최근 40만 국면에서 512개를 무작위로 뽑아 AdamW 한 스텝을 밟습니다.

loss = − Σ π·log p + 1.0 · (z − v)²
π the MCTS visit distribution  →  p the network's policy. Cross-entropy: “guess what search concluded.”
π MCTS 방문 분포  →  p 신경망의 정책. 교차 엔트로피: “탐색이 내린 결론을 맞혀라.”
z who actually won, from this player's side  →  v the network's guess. Squared error: “know when you are losing.”
z 이 국면의 차례인 쪽 기준으로 실제 승패  →  v 신경망의 예측. 제곱 오차: “질 때는 지고 있음을 알아라.”
AdamW · weight_decay 1e-4 · grad_clip 4.0 · lr 2e-3 warmup 200 → cosine → 2e-4

How one game becomes training data한 판이 학습 데이터가 되는 방법

omok/replay.py

Not only the winning games, and not the game as a whole. Every single ply of every single game — won, lost or drawn — becomes one independent training row. A 40-move game yields 40 rows. The loss is computed per position, never per game.이긴 판만 쓰는 것도 아니고, 판 단위로 학습하는 것도 아닙니다. 이기든 지든 비기든, 모든 판의 모든 한 수가 각각 독립적인 학습 행 하나가 됩니다. 40수짜리 판이면 40행입니다. 손실은 국면 단위로 계산되지, 판 단위로 계산되지 않습니다.

The trick is the value target z. It is the final result seen from the side that was about to move at that ply — so in a game black won, black's plies get z = +1 and white's plies get z = −1. One game therefore teaches both "this is what winning looked like" and "this is what losing looked like".핵심은 가치 목표 z입니다. z는 그 수를 둘 차례였던 쪽의 시점에서 본 최종 결과입니다. 그래서 흑이 이긴 판에서는 흑 차례였던 수들은 z = +1, 백 차례였던 수들은 z = −1이 됩니다. 한 판이 "이런 게 이기는 모양이다"와 "이런 게 지는 모양이다"를 동시에 가르치는 셈입니다.

A 39-ply game that black won. Draws give every row z = 0. A lost game is just as useful: its rows carry z = −1 for the side that lost, which is how the network learns what a losing shape feels like.흑이 이긴 39수짜리 판입니다. 비기면 모든 행이 z = 0입니다. 진 판도 똑같이 쓸모 있습니다. 진 쪽의 행에 z = −1이 붙고, 그것으로 신경망은 지는 모양이 어떤 느낌인지 배웁니다.

# omok/replay.py — building the rows from a stored game

for game in shard:                               # won, lost and drawn games alike
    for t, move in enumerate(game.moves):
        player = BLACK if t % 2 == 0 else WHITE  # whose turn at ply t
        pi[t] = game.policies[t]                 # the MCTS visit distribution
        z[t]  = 0.0 if winner == 0 else (+1.0 if winner == player else -1.0)

# omok/train.py — one optimisation step, run 400 times per iteration

planes, pi, z = buffer.sample(512)   # 512 random *positions*, any games
planes, pi    = augment(planes, pi)  # a random one of the 8 symmetries

logits, v   = net(planes)
policy_loss = -(pi * log_softmax(logits)).sum(-1).mean()  # match the search
value_loss  = mse(v, z)                                   # match the outcome
loss = policy_loss + 1.0 * value_loss

loss.backward(); clip_grad_norm_(net, 4.0); opt.step()  # AdamW

So the 512 positions in one batch are drawn at random from the last 400,000 stored positions — different games, different iterations, different plies, all mixed. Nothing is trained "game by game", and no game is filtered out for having been lost.따라서 한 배치의 512개 국면은 최근 40만 국면에서 무작위로 뽑힙니다. 서로 다른 판, 서로 다른 반복, 서로 다른 수순이 뒤섞입니다. "판 단위"로 학습하는 부분은 어디에도 없고, 졌다는 이유로 걸러지는 판도 없습니다.

Rotate a gomoku position 90°, or mirror it, and it is still the same position — the right move just moves with it. So every stored position is really eight, and each training sample gets a random one of the eight. The network stops memorising corners and starts learning shapes.

오목 국면을 90° 돌리거나 뒤집어도 같은 국면입니다. 좋은 수도 함께 따라 움직일 뿐입니다. 그래서 저장된 국면 하나가 사실은 여덟 개이고, 학습 샘플마다 그중 하나를 무작위로 씁니다. 신경망은 구석의 좌표를 외우는 대신 모양을 배우게 됩니다.

Backpropagation: where the gradient actually comes from역전파: 기울기는 실제로 어디서 오나

A natural guess is that the forward pass already works out the gradients, and backward just multiplies them together. Half of that is right. The forward pass caches values, not gradients — the derivatives are computed on the way back, from those cached values.

순전파가 이미 기울기를 계산해 두고 역전파는 그걸 곱하기만 한다고 짐작하기 쉽습니다. 절반은 맞습니다. 순전파가 저장하는 것은 기울기가 아니라 값이고, 미분은 돌아오는 길에 그 저장된 값으로 계산됩니다.

Proof it is values, not gradients기울기가 아니라 값을 저장한다는 증거

omok/backends/torch_backend.py:125
@torch.no_grad()  def predict(...)   ← on the MCTS path
                  def train_step(...)  ← no decorator

The decorator tells PyTorch not to build the graph at all. If the forward pass had already produced the gradients, turning it off would save nothing — but it is exactly what lets self-play run 8,541 positions per second. What it actually saves is memory: at batch 512 one trunk activation is이 데코레이터는 그래프를 아예 만들지 말라는 뜻입니다. 순전파가 이미 기울기를 만들어 뒀다면 이걸 끈다고 아낄 게 없겠죠. 실제로 아끼는 것은 메모리입니다. 배치 512에서 trunk 한 층의 activation은

512 × 96 × 15 × 15 × 4 bytes ≈ 44 MB  ×  13 layers to keep ≈ 570 MB

Held during training, zero during inference. That memory is the cache the backward pass reads.학습 중에만 붙들고 있고 추론 때는 0입니다. 그 메모리가 바로 역전파가 읽는 캐시입니다.

The exact scalar that gets differentiated미분되는 정확한 스칼라

L = −(1/B) · Σb Σa πb,a · log pb,a + 1.0 · (1/B) · Σb (vb − zb)²
B = 512 · a = 225 points · value_loss_weight = 1.0
Not in this formula: weight_decay 1e-4 — AdamW is decoupled, it shrinks the weights inside opt.step() rather than adding an L2 term to L.
이 식에 없는 것: weight_decay 1e-4 — AdamW는 decoupled 방식이라 L에 L2 항을 더하는 대신 opt.step() 안에서 직접 가중치를 줄입니다.
Also not in it: target_entropy — computed under with torch.no_grad() at line 157. Logging only.
역시 없는 것: target_entropy — 157행에서 with torch.no_grad()로 계산합니다. 로깅 전용입니다.

Ctrl-C는 진행 중인 작업 단위를 끝내고 저장한 뒤 종료하며, make resume가 단계 중간부터 이어받습니다. 학습 프로세스를 SIGKILL로 죽인 뒤 복구되는지 확인하는 테스트도 있습니다.
